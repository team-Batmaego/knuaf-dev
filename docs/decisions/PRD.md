## 1. 누구를 위해 (Target Audience)
- 한국농수산대학교(한농대) 학생 등 창업논문 작성이 필요한 사용자 (형님 피드백 "한농대 학생 — 뇌 빼고 쓰는 쉬운 UI", 2026-10-18, v5 설계/ 형님 원문 "뇌 빼고 쓰는 사람, 지능이 낮은 사람도 쉽게 쓸 수 있는 UI,UX를 지향해야한다.", 2026-11-03, 오모냥 기록(11-03))
- 비전공 여부 및 컴퓨터/AI 도구 숙련도별 추가 페르소나 정의: 비어 있음 (형님 원문에는 비전공/도구 비숙련 제한이 없으므로 임의로 좁히지 않고 6절 열린 질문으로 분류)

<!-- 2. 풀 문제: 사용자가 겪는 핵심 불편(Pain Point, 고통 지점)과 이 작업으로 해결하려는 문제를 적는다. -->
## 2. 풀 문제 (Problem Statement)
- 문서 미리보기가 외부 앱이나 별도 레이어로 겹쳐 열려 맥락이 끊기고, 생성된 산출물 파일에 학생들이 쉽게 도달하지 못하는 불편 (형님 원문 "v0.6.0 공개 당장 안되겠다. 인앱 문서가 다른 레이어로 열리는 수준이라 부품들 붙이고 그냥 배포해야겠음. 지금은 좀 부끄럽다", 2026-11-04, 오모냥 기록(11-04) / 형님 원문 "채팅 파일 버튼은 바로 열기면, 인앱 문서는 어떻게 켜는건가? 기본적으로 인앱부터 켜야지." 및 "최소한 산출물이라도 인앱에서 볼 수 있게 하는 게 우리 주 목적이자 강점", 2026-11-03, 오모냥 기록(11-03))
- 명확한 요구사항 정의서와 결정 문서 없이 작업을 진행하여 전체 로드맵과 세부 결정 사항을 인지하기 어려운 문제 (형님 원문 "저런 결정 문서가 너무 필요하다. 못해서 PRD와 5층 설명을 문서화로 해서 내가 계속 인지하면서 작업을 해야하는데, 지금 거의 주먹구구식으로만 다 작업을 하고 있어서 슬프네. 이런 걸 타파하고 효율적으로 하고 싶어. 하다못해 맥북 바탕화면에 todos 위젯 같은걸 표시하던지 다른 방식으로 내가 로드맵 자체를 인지하고 있으면 좋을 것 같아.", 2026-11-04, 발주서(11-04) / 축약본: 오모냥 기록(11-04))

<!-- 3. 성공 기준: 문제가 잘 해결되었는지 판단하는 측정 가능한 목표나 확인 조건을 적는다. -->
## 3. 성공 기준 (Success Criteria)
- 학습 비용 없이 누구나 바로 직관적으로 누르고 진행할 수 있는 쉬운 UI/UX 달성 (형님 원문 "뇌 빼고 쓰는 사람, 지능이 낮은 사람도 쉽게 쓸 수 있는 UI,UX를 지향해야한다.", 2026-11-03, 오모냥 기록(11-03))
- 외부 뷰어를 띄우지 않고 앱 내부에서 산출물 문서(Word, Excel 등)를 곧바로 열어 확인 가능한 인앱 뷰어 체계 완성 (형님 원문 "최소한 산출물이라도 인앱에서 볼 수 있게 하는 게 우리 주 목적이자 강점", 2026-11-03, 오모냥 기록(11-03))
- 성공 여부는 형님이 학생들의 평가를 직접 듣고 판단한다 (형님 원문 "이건 학생들의 평가를 내가 직접 들어서 판단해야 할 것 같음.", 2026-11-05, 오모냥 전달(11-05), DECISIONS STR-03)
- 숫자로 재는 성공 지표: 비어 있음

## 4. 하지 않을 것 (Non-Goals / Out of Scope)
- 논문GUI 학생 그림 점검 기능에 형님 돈으로 유료 멀티모달(Jev) 호출 적용 제외 (형님 원문 "1,2번은 넣긴 할텐데 그건 나중의 일 아닌가? 메모바람. 3번은 굳이 내 돈으로 학생을??? 안해도 될 듯.", 2026-10-28, 오모냥 기록(10-28))
- macOS 앱 배포 시 유료 애플 개발자 코드 서명 및 공증(연 99달러) 진행 보류 (형님 원문 "다 권고대로, Q4는 보류", 2026-10-31, 오모냥 기록(10-31))
